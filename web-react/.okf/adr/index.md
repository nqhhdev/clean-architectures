Why the codebase is the way it is. Supersede an accepted ADR rather than editing it. ADR 0001 is superseded by 0010 and ADR 0002 by 0012; the rest of 0003-0009 stay in force and 0010-0018 extend them.

# Concepts
* [ADR 0001: Layers ui, domain, data, config and utils, enforced by lint; one OKF bundle per stack](0001-layers-and-boundaries.md) - Organise src/ by architectural role, enforce the dependency directions with eslint-plugin-boundaries, and keep this stack's knowledge in its own .okf/ bundle.
* [ADR 0002: Result<T> for expected failures, exceptions for the unexpected](0002-result-over-exceptions.md) - Return business and transport failures as Result values so they are visible in signatures; keep exceptions for bugs and faults.
* [ADR 0003: TanStack Query for server state, React state for local UI state](0003-state-management.md) - Server data lives in the query cache; local UI state uses React state and context; each shared piece has one owner.
* [ADR 0004: TanStack Router](0004-tanstack-router.md) - Typed routes and search params, with guards in beforeLoad.
* [ADR 0005: Generated zod schemas parse every API response at the data boundary](0005-zod-at-the-data-boundary.md) - Responses are parsed by schemas generated from the OpenAPI file, mapped to domain models, and invalid list items are skipped and logged; hand-written zod is only for env.
* [ADR 0006: Strict TypeScript, ESLint flat config and Prettier; generated code is ignored](0006-strict-typescript-and-lint.md) - Strict compiler options and type-checked lint gate every change; generated files are git-ignored and left out of lint, coverage, docs and okf.py.
* [ADR 0007: Four test tiers and an 80% coverage gate](0007-test-tiers-and-coverage.md) - Unit, component, MSW integration and a Playwright smoke test; line coverage of non-generated code is at least 80%.
* [ADR 0008: openapi/emails.yaml is the single schema source; orval generates types and zod schemas](0008-openapi-contract-as-single-schema-source.md) - One OpenAPI file in this stack drives TS types and zod schemas; it is replaced by the real .NET spec by changing one path or URL.
* [ADR 0009: Cookie session and CSRF validation are owned by the API](0009-cookie-session-and-csrf-owned-by-the-api.md) - The SPA sends credentials and a CSRF header and never stores tokens; issuing cookies and validating CSRF belong to the API or a BFF.
* [ADR 0010: Hexagonal layers with a lint-enforced allow-matrix and injected services; one OKF bundle per stack](0010-hexagonal-layers-boundaries-and-services.md) - src/ is split into domain, application, adapters, ds, features and app; an allow-matrix enforced by eslint-plugin-boundaries fixes who may import whom, and services reach features through one context.
* [ADR 0011: ds/ owns tokens and components; features may add layout-only CSS Modules](0011-design-system-and-styling.md) - Design tokens are CSS variables declared in ds/ with light and dark via [data-theme]; features compose ds components and may own CSS Modules for layout only.
* [ADR 0012: Adapters never throw for expected failures; Result is generic and AppError is a closed union](0012-result-and-app-error.md) - Ports return Promise<Result<T, AppError>> with four error kinds; queries.ts is the one place an Err is turned into a thrown QueryError for TanStack Query.
* [ADR 0013: Query defaults, per-feature query keys and a router context with guards in beforeLoad](0013-data-loading-and-routing.md) - TanStack Query defaults and key conventions, plus TanStack Router context, beforeLoad guards, loaders that prefetch and nested error components.
* [ADR 0014: SessionService is a port and the HTTP client is the single 401 handler](0014-session-and-single-401-handler.md) - Session state sits behind a port, only the HTTP client reacts to 401, and start-up work is idempotent so React StrictMode double invocation is safe.
* [ADR 0015: Translation keys are derived from en.json; locales live in src/locales/](0015-i18n-keys-from-en-json.md) - en.json is the source, TranslationKey is derived from it so a missing key is a type error, and a test checks key parity across locales.
* [ADR 0016: Compiler flags, the @/ alias and a fixed lint rule set](0016-compiler-flags-alias-and-lint-rules.md) - The @/ alias, the contents of pnpm check, and the extra lint rules and plugins, each added in the step where it has code to check.
* [ADR 0017: Test harness with real providers, typed fakes per port and MSW in mock mode](0017-test-harness.md) - renderWithProviders wires real providers around fake ports; adapter tests use MSW; Playwright runs against a mock-mode build served by vite preview.
* [ADR 0018: One CI workflow runs pnpm check; deploy reads /env.js at runtime](0018-ci-and-runtime-delivery.md) - One workflow with a gate job runs install, audit and pnpm check; the deployed image serves static files, a runtime /env.js and a CSP generated at start.
* [ADR 0019: Client-side security baseline S1-S7 with lint, scan and bundle checks](0019-client-side-security-baseline.md) - Web form of rules S1-S7: no secrets, https, cookie session without script-reachable tokens, redacted logs, a bundle without source maps or mock code, audited dependencies, metadata-only request logs.
